# oplus-votable

通过 OPLUS 内核的 Votable 电流投票接口，根据电池电压动态调整 UFCS / PPS 的电流控制目标。

## 当前默认预设

v0.9.27 将 2026-10-23 手机上的控制页设置作为新版默认。缺少设置文件时采用此预设，页面初始值和已有“恢复默认”按钮与之同步；升级保留用户已经保存的值，不执行恢复操作。

## 电流投票

充电驱动通过 Votable 汇总不同策略的电流请求。模块使用对应协议的强制投票节点：

- UFCS：`/proc/oplus-votable/UFCS_CURR/`
- PPS：`/proc/oplus-votable/PPS_CURR/`

接管时先把目标值写入 `force_val`，再写入 `force_active=1` 开启强制投票。每次目标变化都重复这个顺序，因为只修改 `force_val` 不会触发驱动重新投票，需要重写 `force_active` 才能触发回调。

## 根据电压调节目标

模块从配置的“投票初始值”起步，按“监控时间”循环读取 `/sys/class/power_supply/battery/voltage_now`，并与当前协议的设定电压比较：

- 电压低于“设定电压 + 升流截止压差”：按“提升步进”增加投票值。
- 电压超过设定电压：按“降低步进”减小投票值；调度迟到时，按实际经过的监控周期补齐降流步数，最低降到 1000 mA。升流每轮只走一步，不补积欠步数。
- 电压处于两者之间：保持投票值不变。

升流截止压差为负值时，会在目标电压下方形成一个保持区间，减少频繁升降。普通电压调节的降低下限为 1000 mA，目标不超过该协议配置的投票上限；上限被调低时，下一轮会将目标收敛到新上限。

首次接管、切换电量区间或恢复间断充电时，先检查电压；已经达到设定电压时将起步目标限制到 1000 mA 以内，不先写入高初始值。电压读数为零、无效或读取失败时，同样保守限流并禁止升流，不抬高已有的更低目标。最后一次超出设定值后至少等待一秒，并且电压低于升流截止线，才允许再次逐步升流。

循环使用 Shell 内建读取，电量与间断区间规则仅在文本变化时重新校验，避免每轮反复启动大量进程。监控时间是包含读取、计算和写入开销的目标周期；实际速度仍受系统调度及驱动响应影响，不能保证硬实时。`auto-live` 中的 `LOOP_MS` 保存实际循环间隔，`CONTROL_VOLTAGE_UV` 和 `CONTROL_LIMIT_MV` 保存这轮控制使用的读数与目标。电压限流、恢复等待和投票写入失败会记入事件日志。

UFCS 设定电压可调范围为 3800–4660 mV，默认 4560 mV；PPS 为 3800–4560 mV，默认 4460 mV。这里的设定电压是电池电压比较阈值，用于调整电流投票。

这些设置不修改电池或充电驱动的超压保护阈值，也不代表电池允许提高到该电压。模块会检查 `force_val` 和 `force_active` 的写入及回读结果，失败时显示异常并重试；节点确认不能证明实际电流已经完成变化。

### 提前收回无效投票余量

UFCS / PPS 在原控制循环内自动学习有效投票上限，不改写用户保存的投票上限。后台每 500ms 采样电池充电电流；投票写入后至少等待 1500ms，并遵守恒压页更长的等待时间，再收集至少 1 秒的稳定读数。每次向下试探 200mA，实际电流没有明显减少时继续收回余量；检测到实际电流减少时，以上一档作为学习上限，按原升流规则恢复，不立即跳回用户上限。后续升流受学习上限约束，避免投票重新堆高。约每 10 秒小步试探输出能力是否恢复，向上步进取原升流步进与 200mA 的较小值，恒压期间还受恒压升流上限约束；无改善时收回该次试探，并再次向下检查。

这里只比较同一电流接口在调整前后的变化，不把电池电流数值直接当作输入侧投票，也不根据功率反推投票；OPLUS 电池节点按 mA 读取，其它标准电池接口按 µA 换算。只有报告 Charging、负方向且有效的充电电流才参与学习。电流波动超过窗口最高读数的 3%（最低容许范围 150mA）时重新等待；下探响应门槛为参考电流的 1%（最低 75mA），上探为 0.25%（最低 25mA）。这些是试探判定参数，不是电流测量精度。

距离协议电压上限不足或等于 30mV、进入恒压正常调节范围、触发提前降流或电压恢复等待时停止试探，继续原有电压控制并保留学习上限。温控限流、间断暂停、写入失败、协议/电量区间/用户上限变化、无效电流或异常时钟会清除学习，待条件恢复后重学；间断阶段结束前 3 秒不新试探。读不到可靠电流时回退原电压算法。学习上限仅在当前控制进程内保存，系统接管、重新接管或重启后重新学习。事件日志记录试探方向和生效点，auto-live 的 HEADROOM_CAP_MA、HEADROOM_PROBE、HEADROOM_CURRENT_MA 供核对；0 上限表示尚未学习。电池负载和读数延迟仍可能影响判断，小步试探可能造成短暂电流变化；此功能不调整快速降流门槛或原厂保护。

### 接近上限时提前降流

控制页“电流控制”提供两项配套参数，自动保存并支持恢复默认：提前降流压差 −50–0mV，默认 −10mV；提前降流步进 0–1000mA，默认 200mA。压差小于 0 时才允许编辑步进，两项分别为负压差与正步进时才提前降流。把压差改回 0 会保留已存步进，恢复默认会设为 −10mV 和 200mA。它们是 UFCS / PPS 共用参数，不改变已有电量区间格式。

电压达到“协议设定电压 + 提前降流压差”且不超过协议设定电压时，每次按配置的步进降低投票，下限为 1000mA。例如 4560mV、−10mV、50mA 表示在 4550–4560mV 区间每次下调 50mA。每次成功写入后采用恒压页的“调整后等待时间”（默认 1500ms）等待响应，不补扣错过的监控周期，等待期间也不因电压短暂回落立即升流；恒压已启用时还遵守它最近一次写入的等待。提前降流触发时，同一轮不叠加恒压普通降流。超出设定电压后使用原有恒压或快速降流分级，温控、间断暂停和系统接管继续优先；无效读数仍保守限流。此参数调整的是电流投票，不能保证实际电压完全不越界。

### 交回系统完成末段充电

强制电流投票可能影响系统末段收尾。100% 是电量显示，和驱动报告 `Full` 是不同状态；原有恒压逻辑在 `Full` 后停止升流，但仍保留投票。

控制页的“系统接管”提供两个独立选项，均自动保存：

- **按电量交回系统**：默认关闭，接管电量默认 100%，可调 0–100%。达到阈值后核对并撤销本模块的强制投票，结束模块的间断暂停，由系统控制末段充电。会话标记按本次启动与阈值保存，守护重启、电量回落或充电协议切换不会重新抢回；拔线、关闭此开关或改变阈值后重新判断。
- **旁路供电时交回系统**：默认开启。只读当前用户的 `Settings.System.bypass_charge_state`（本机系统电池程序使用 1 开启、0 关闭），约每秒检查。开启旁路后交回系统，关闭后按原有电压和温控规则恢复模块控制；若电量接管仍生效，则继续由系统控制。读取失败或值异常时暂停接管并显示原因；系统未提供此开关时显示联动不可用，保留原有控制。

两项均独立于恒压开关，适用于 UFCS / PPS；自动监测与协议开关仍是模块恢复控制的前提。撤销或 MMI 恢复失败会显示异常并重试，不会显示已交回成功。此功能不改动系统旁路开关、充满条件和保护阈值，也不关闭独立的温度伪装功能。

控制进程从 WebUI 启动时，若继承了 Android 的应用 cgroup v2 冻结组，会先将自身移到根进程组并确认自身 PID，后续子进程随之脱离应用冻结。迁移失败则报告异常，不新建强制投票；从系统服务启动、已经位于其它组的进程保持原样。此操作不解冻管理器或其它应用，也不修改系统冻结开关。

### 后段电压反馈

控制页的“恒压调节”可独立开关（默认开启），七项参数均支持滑条、数字输入和一键恢复默认，自动保存到模块私有目录，重启后保留：

| 参数 | 默认值 | 可调范围 |
| --- | --- | --- |
| 启用电量 | 80% | 0–100%，0 表示全部电量生效 |
| 目标压差 | −5mV | −50–0mV |
| 保持压差 | ±5mV | ±1–15mV |
| 正常升流步进上限 | 50mA | 10–500mA |
| 降流步进上限 | 100mA | 10–1000mA |
| 调整后等待 | 1500ms（1.5 秒） | 200–10000ms |
| 快速降流触发压差 | +15mV | 0–+50mV，0 表示一超过设定电压就快速降流 |

电量达到启用值后，UFCS/PPS 自动切换为慢速电压反馈，直到电量低于“启用值 − 2%”（最低 0%）、关闭开关或协议断开；已进入后段时电量读取暂时异常不会退回快速升流。修改启用电量时立即重新判定。恒压目标取「协议设定电压 + 本页目标压差」，独立于普通自适应使用的通用或区间升流截止压差。例如设定 4560mV、目标压差 −20mV 时，恒压目标为 4540mV；−50mV 时为 4510mV；0mV 时为 4560mV，不再固定扣除 20mV。

电压在软目标的保持范围内不变；偏低时按正常升流上限增加投票，偏高时按降流上限减少投票。实际升降步进取本页上限与当前电量区间或通用步进的较小值。每次投票写入并回读成功后等待配置的时长再作正常调整，让驱动、电流和电压有时间响应；修改等待时间会以最近写入时刻重新计算期限。恒压期间，略高于协议设定电压、但未达到「设定电压 + 快速降流触发压差」（默认 +15mV）时，同样只走一个降流步进并遵守写入后等待，不累计补扣监控周期；即使在保持范围内也会在等待结束后向下调整。超过设定电压且达到配置的快速降流压差时，恢复原快速降流和调度补步，不等待软调节计时；0mV 表示一越界就快速降流，+50mV 表示达到设定值 +50mV 时才切换快速降流。修改压差即时参与判断，不重置等待时间。这里是软件反馈分级，不会提高硬件保护阈值。无效电压或时钟采用保守限流，温控继续优先。系统报告 `Full` 时不再因低电压继续升流，超过设定电压仍会按上述分级降流。等待过短、步进过大可能重新引起振荡。

快速降流触发压差调大将延后快速降流，可能增加瞬时越界。目标压差接近 0mV 时提前量更小，瞬时越界风险可能增加。保持范围不会屏蔽超过协议设定电压的下调；明显超限时快速降流优先于保持范围和等待。

后段切换电量区间时保留当前目标、立即应用新上限，不重新跳到新段初始值，也不会因轻微越界直接夹到 1000mA，而是继续分级调节；首次在后段接管时将起步值限制在 1000mA 以内，间断恢复继续先检查电压和温控。普通调节下限仍为 1000mA。这是通过电流投票逼近电压目标的外层反馈，不修改 FV、硬件恒压或过压保护参数，无法保证电池电压绝无瞬时越界。`auto-live` 的 `CONTROL_CV` 和 `CONTROL_TARGET_MV` 可查看当前是否处于后段及软目标；闭环模型及隔离测试不能代替真实充电验证。

## 根据电量选择参数

UFCS 的“电量百分比投票控制”默认关闭。开启后，后台读取 `/sys/class/power_supply/battery/capacity`，按当前整数电量选择区间。区间包含两端且不允许重叠，例如 0–20%、21–40%，100% 也可单独设置。

每个区间独立保存投票上限、投票初始值、监控时间、提升步进、降低步进和升流截止压差。命中时覆盖 UFCS 投票上限及对应通用参数；未添加区间、未命中、读取不到有效电量或配置不可读时使用通用设置。PPS 继续使用其协议设置及通用参数。

接管或切换电量区间时以对应初始值起步，并先受区间投票上限和温控限制约束。当前区间内修改上限、监控时间、步进和截止压差，下一轮控制即生效；初始值在下次接管或区间切换时使用。区间以完整参数组原子保存，不修改通用设置；关闭开关保留已保存的区间。后台独立运行，页面关闭后仍会按电量切换参数。

## 根据温度限制目标

温度控制默认开启。开启后，后台每秒读取真实电池温度 `/sys/class/power_supply/battery/temp`，达到设定上限时立即将投票目标限制到温控限流值，并禁止升流。温度降至“温度上限 − 恢复温差”及以下后解除，再按原有电压规则和提升步进逐渐恢复，不直接跳回先前的大电流目标。

温度上限默认 50°C，可调 20–60°C；限流值默认 1000 mA，可调 500–5000 mA；恢复温差默认 2°C，可调 1–5°C。温控不会将原本更低的目标抬高，也不会突破协议投票上限。首次接管也先检查温度。读温失败时禁止升流，并将目标限制到 1000 mA 与温控限流值中的较小值，正常读温且满足恢复条件后才解除限制。

温控依赖自动监测及 UFCS / PPS 协议接管，设置与控制不依赖页面打开。温度页每秒刷新读数和后台状态。这里的温控是限制电流投票，不会改写温度传感器数值，也不等于停止充电。

## 间断充电

间断充电默认关闭，对已接管的 UFCS / PPS 生效。充电时间默认 60 秒，可调 1–1200 秒；断开时间默认 1000 毫秒，可调 0–60000 毫秒。充电计时结束后先核对本模块租约和投票保存值，再向 `/sys/devices/virtual/oplus_chg/battery/mmi_charging_enable` 写入 `0` 请求停充，时间到后写入 `1` 恢复。此动作采用参考模块的 MMI 停充/恢复原理，时长使用本模块的设置。

暂停期间停止电压升降步进，保留投票保存值，同时检查电量区间和温控。恢复 MMI 后，保留暂停前的控制目标，先应用当前区间上限、温控及电压限制，再恢复电压自适应；不再每次跳回投票上限。普通阶段切换区间使用新段初始值，后段电压反馈则保留当前目标并应用新上限。阶段计时使用单调开机时间，从停充或投票恢复回读成功后开始。控制循环按正常间隔检查设置，不会阻塞整个暂停周期。

未添加生效区间时对全部电量循环；添加后仅在指定区间生效，支持 0–80% 或 0–40%、60–80% 等多个不重叠区间，包含两端。离开区间、关闭功能或计时读取失败时恢复正常投票；进入区间、修改时间或切换协议时重新从完整充电阶段开始。断开时间为 0 时持续正常充电。设置持久保存，控制不依赖页面打开。

仅当 MMI 原本为 `1` 时接管，并在停充前保存本次启动和控制进程标记。关闭功能、总监测、拔线或正常退出时恢复自有停充；进程崩溃后由守护恢复，恢复失败保留标记并重试。不会开启其它来源主动关闭的 MMI。MMI 停充可能让协议暂时离线：暂停计时结束后先恢复 MMI，再等待协议重新在线。实际停充效果、协议是否重新协商及持续时间取决于驱动和充电器，不能将该动作等同于物理 USB 拔插。

## 充电记录与曲线

底部“记录”页默认优先显示正在进行的充电记录，没有正在记录时自动显示最近一次记录；手动选择历史记录后保留选择，点击“实时”或“最近一次”恢复自动选择。v0.9.29 使用紧凑布局：顶部的小电量圆环旁汇总充电状态、起止时间、时长和电量变化；五项参数和双电芯开关按两列排列，当前数值左侧保留该指标整次记录的最高值。图表高度随可用屏幕高度调整，优先在一屏显示主要数据、图表和折叠入口；屏幕很小、放大字体或展开详情时仍可滚动。峰值从整次原始记录计算，不随图表缩放或点选变化。

功率蓝色、电量绿色、温度红色、电压黄色、投票值黑色，五条曲线全部以实线叠加在原生 Canvas 图表中，共用时间轴，各自按独立范围缩放。点击参数名称切换左侧纵轴的单位和刻度，五条曲线始终显示；不同曲线的高度不能直接比较数值大小。电量固定 0–100%；温度默认显示 30–50°C、电压默认 3–5V，遇到超出范围的有效读数自动扩展；功率上限按峰值预留 20% 空间后取整，最低 30W，投票以 mA 显示并自动扩展刻度。全程横轴至少显示 5 分钟，时间范围缩放后按实际选择显示。单指触摸图表可同步查看同一时刻的五项参数，也支持键盘逐点选择。双指张开放大时间范围、捏合缩小，双指移动可平移，缩放范围限制在本次记录内，最窄为整次时长的 2%；手势期间仅重绘，结束后读取所选时间的细节，滑条同步更新。图表区域用于选点和缩放，上下滚动页面请在图表外操作。右上角打开历史记录选择器，每页 20 条；底部折叠区提供时间缩放、数据表和读数说明。

独立后台目标每 0.2 秒读取一次电池节点，与电流控制开关和页面是否打开无关；采样时间包括读取与保存的开销，并非严格 5Hz。连接 USB、交流或无线电源后开始记录，拔掉电源后结束；充满、温控限流与间断充电不会拆分记录。重启或连续采样中断超过 10 秒时另建记录，无法读取的数值留空。横轴使用真实采样经过时间，不按点数乘固定间隔推算。实时页面目标 0.2 秒刷新，慢请求不叠加，长记录会降低刷新频率。

功耗按电池电压与电流绝对值计算，代表电池端功率，不等于充电器输入功率，也不区分充放电方向。`oplus battery` 驱动的 mA 电流先换算成 µA，其它标准电池接口按 µA 处理；电压按 µV、温度按 0.1°C 读取，不使用外壳温度伪装值。

投票值采样核对本模块租约的启动标识、存活进程、UFCS/PPS 协议及节点中的 `force_active` / `force_val`，只记录实际生效且仍匹配租约的目标，不等于实测电池电流。未接管、撤销或无法核验时留空；间断暂停充电时保留的投票仍按实际值记录。新 CSV 在原六列后追加第七列投票值，旧记录继续读取并计算原有四项峰值，未保存的历史投票值显示“—”。

“双电芯”默认关闭，开启后将估算功率及其峰值乘 2，用于串联双电芯且电压节点提供单芯电压的口径；电压曲线仍显示节点电压，投票值不翻倍。如果电压节点已经是整包电压，应关闭此开关。开关只影响实时和历史图表、数值及数据表的显示，保存在当前 WebUI 中，不改写原始记录或充电设置。

记录保存在 `/data/adb/oplus-votable/charging-history/`，每次连接对应独立 CSV，不自动删除，升级和卸载保留已有数据。长记录按真实时间分桶，保留各指标的峰值和低谷，绘制时再按屏幕分桶取极值；缩放后重新读取所选范围，原始 CSV 保留全部采样。短于实际采样间隔的变化仍可能漏采，图表不能独立证明某个低谷的具体原因。数据只保存在手机本地。列表只接收字段完整的摘要；单条摘要损坏时保留原文件、显示异常提示，其余记录仍可查看。

## 接管与撤销

模块读取 OPLUS MMS 协议状态，只在自动监测开启、有且仅有一个协议在线、且该协议为已启用的 UFCS 或 PPS 时接管。VOOC / SUPERVOOC 只读识别，不主动控制电流。

接管时保存当前启动标识、进程、协议和目标值，作为本模块的控制租约。协议断开、切换或相关开关关闭时，核对租约及节点中的 `force_val`，确认仍属于本模块后写入 `force_active=0`，撤销强制投票。守护进程按租约尝试恢复残留控制。

## 温度伪装与 horae

温度伪装默认开启。开启后先通过 `dumpsys horae testmode` 请求测试模式，再把配置温度写入 `/proc/shell-temp` 的 0/1/2 通道并将节点设为只读，保留 horae 读取权限。默认 36.0°C，可调 20.0–45.0°C；调整温度会重新应用。调用顺序参考 [OWC](https://github.com/Sillybomo/OWC/blob/master/vtools/warp_charge.sh#L286-L322)。

v0.9.28 新增自适应伪装，默认关闭，温差预设 5°C，可调 0–20°C（整数）。独立后台每秒读取 `/sys/class/power_supply/battery/temp` 的真实电池温度，减去温差后写入相同的三个外壳通道，例如真实 40°C、温差 5°C 时写入 35°C。它不会以已经伪装的外壳读数作为下一轮输入，电池温度保护与充电记录仍使用真实电池温度。页面显示最近采样的真实温度和实际写入目标。

固定伪装、自适应伪装与关闭共用一个原子保存的模式设置，开启一种自动关闭另一种；可以两种都关闭。修改温差不会自行开启自适应模式，切回固定模式保留原先的固定温度。自适应更新独立于自动监测开关，关闭页面后继续运行，开机恢复保存的模式；真实温度无效时解锁节点并请求恢复正常温控，显示异常并每秒重试。独立服务约每 5 秒检查后台是否存活，进程不存在或采样过期时不显示应用成功。

关闭或卸载时，通过 `dumpsys horae testmode false` 请求恢复正常模式，并恢复节点可写。部分系统（本机已验证）忽略 `false`，仍会开启测试模式；模块检测到这一情况时，仅在本次开机有本模块开启记录的前提下短暂重启 `horae`，核验退出后才报告恢复成功。开机根据保存的开关重新应用；模式命令最多等待 3 秒，失败时不报告应用成功，页面显示本次开机最后一次命令结果。该结果表示命令执行情况，不代表持续监测服务内部模式。

此功能改变系统使用的外壳温度读数，可能影响系统热控；模块的电池温度控制仍读取真实电池温度。测试模式的支持情况和实际效果取决于系统实现。

## 设置与显示

WebUI 通过 Root 管理器提供的接口调用模块脚本。参数保存在 `/data/adb/oplus-votable/`，后台每轮读取配置，因此修改设置不依赖页面持续打开。状态、USB 读数、Votable 和日志通过固定路径的只读接口显示。

后台命令优先通过异步进程回调返回，页面切换不等待命令执行完成。拖动滑条时暂停定时读取，正在编辑的值不被后台刷新覆盖，松手后保存并回读确认。区间汇总响应异常时独立重读区间设置，持续失败只停用区间编辑，不中断其它控制状态显示，也不改写已保存的配置。

模块调整的是内核电流投票目标。实际充电电流还受驱动策略、温控、充电阶段、充电器和线材等因素影响，温控限流的实际效果需要实机验证。
