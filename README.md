# oplus-votable

通过 OPLUS 内核的 Votable 电流投票接口，根据电池电压动态调整 UFCS / PPS 的电流控制目标。

## 电流投票

充电驱动通过 Votable 汇总不同策略的电流请求。模块使用对应协议的强制投票节点：

- UFCS：`/proc/oplus-votable/UFCS_CURR/`
- PPS：`/proc/oplus-votable/PPS_CURR/`

接管时先把目标值写入 `force_val`，再写入 `force_active=1` 开启强制投票。每次目标变化都重复这个顺序，因为只修改 `force_val` 不会触发驱动重新投票，需要重写 `force_active` 才能触发回调。

## 根据电压调节目标

模块从配置的“投票初始值”起步，按“监控时间”循环读取 `/sys/class/power_supply/battery/voltage_now`，并与当前协议的设定电压比较：

- 电压低于“设定电压 + 升流截止压差”：按“提升步进”增加投票值。
- 电压超过设定电压：按“降低步进”减小投票值。
- 电压处于两者之间：保持投票值不变。

升流截止压差为负值时，会在目标电压下方形成一个保持区间，减少频繁升降。每次调节后，投票值限制在 1000 mA 到该协议配置的投票上限之间；上限被调低时，下一轮会将目标收敛到新上限。

## 接管与撤销

模块读取 OPLUS MMS 协议状态，只在自动监测开启、有且仅有一个协议在线、且该协议为已启用的 UFCS 或 PPS 时接管。VOOC / SUPERVOOC 只读识别，不主动控制电流。

接管时保存当前启动标识、进程、协议和目标值，作为本模块的控制租约。协议断开、切换或相关开关关闭时，核对租约及节点中的 `force_val`，确认仍属于本模块后写入 `force_active=0`，撤销强制投票。守护进程按租约尝试恢复残留控制。

## 设置与显示

WebUI 通过 Root 管理器提供的接口调用模块脚本。参数保存在 `/data/adb/oplus-votable/`，后台每轮读取配置，因此修改设置不依赖页面持续打开。状态、USB 读数、Votable 和日志通过固定路径的只读接口显示。

模块调整的是内核电流投票目标。实际充电电流还受驱动策略、温控、充电阶段、充电器和线材等因素影响；本模块当前没有额外的温度限制逻辑。
